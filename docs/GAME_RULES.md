# GAME_RULES.md

# マルチプレイヤー領土ゲーム — 形式的ルール仕様

このドキュメントは、ゲームメカニクスを厳密に定義します。
本仕様はシミュレータ実装における正本です。

すべての実装（teacher、rollout、C++ engine、feature encoder）は、この文書に厳密に従う必要があります。

---

# 1. 定数と定義

## 1.1 盤面

- 盤面サイズ: N × N（N = 10）
- 座標: (i, j)
  - i: 行インデックス（0 = 上端）
  - j: 列インデックス（0 = 左端）

## 1.2 プレイヤー

- プレイヤー数: M（2 ≤ M ≤ 8）
- Player 0: 自分のエージェント
- Players 1..M-1: AIプレイヤー

各プレイヤーは常にちょうど1つの駒を持ちます。

---

# 2. 状態定義

ゲーム状態 S は以下で構成されます。

O[i][j] ∈ {-1, 0, 1, ..., M-1}
マスの所有者
-1 = 無所有

L[i][j] ∈ {0, 1, ..., U}
マスのレベル
U = レベル上限

piece_pos[p] = (x_p, y_p)
プレイヤー p の現在の駒位置

turn ∈ {0, 1, ..., T}

V[i][j]（定数）
マス価値（不変）

初期条件:

- 各プレイヤー p について:
  O[sx_p][sy_p] = p
  L[sx_p][sy_p] = 1
  piece_pos[p] = (sx_p, sy_p)
- それ以外の全マス:
  O = -1
  L = 0

---

# 3. 合法手の定義

位置 (x, y) にいるプレイヤー p について:

## 3.1 到達可能領域

到達可能集合 R_p を次で定義します。

(x, y) から BFS で到達可能な全マス。
移動は O == p のマスのみを通過可能とし、
隣接は4近傍を用います。

## 3.2 移動可能集合

移動可能集合 B_p を次で定義します。

B_p = R_p ∪ {R_p 内のいずれかのマスに4近傍で隣接するマス}

制約:

- 移動先は盤面内でなければならない。
- 移動先に他プレイヤーの駒があってはならない。

自分の現在位置へ移動することは許可されます。

---

# 4. ターン手順

各ターンは必ず以下の順序で処理されます。

---

## Step 1: 同時移動宣言

各プレイヤーは移動先 (tx_p, ty_p) ∈ B_p を選択します。

移動は同時に行われるものとして扱います。

この段階では状態更新は行いません。

---

## Step 2: 衝突解決

全プレイヤーの駒を仮移動したあと:

各マス C について:

P_C を「駒が C に移動したプレイヤー集合」とします。

|P_C| ≤ 1 の場合:
衝突なし。

|P_C| ≥ 2 の場合:
owner = O[C] とする。

    Case A: owner ∈ P_C
        owner の駒のみ生存。
        P_C 内の他プレイヤー駒はすべて「除去」扱い。

    Case B: owner ∉ P_C
        P_C 内の駒はすべて「除去」扱い。

衝突解決後:

- 生存駒は C に残る。
- 除去駒は一時的に盤外扱い。

---

## Step 3: 領地更新

生存駒に対してのみ適用します。

マス C にいるプレイヤー p の生存駒ごとに:

Case 1: O[C] == -1（無所有）
O[C] = p
L[C] = 1

Case 2: O[C] == p（自領地）
L[C] < U なら:
L[C] += 1
それ以外:
L[C] は変化なし

Case 3: O[C] == q != p（敵領地）

    L[C] -= 1

    L[C] == 0 の場合:
        O[C] = p
        L[C] = 1
    それ以外:
        攻撃駒を「除去」扱いにする

注記:
ここで攻撃駒が除去されても、
レベルが0にならない限り、このターンで行ったレベル減少は戻しません。

---

## Step 4: 駒の復帰

このターンで「除去」扱いになった全駒は:

元の位置（移動宣言前）へ戻します。

重要:
元の位置とは、ターン開始時点の piece_pos[p] です。

復帰後、piece_pos[p] は次のように更新されます。

- 生存した場合: 新しい位置
- 除去された場合: 元の位置

---

# 5. 不変条件

- 各プレイヤーは常に少なくとも1マスを所有する。
- 駒が存在するマスは攻撃対象にできない。
  （衝突で除去されない限り、その駒は残るため）
- piece_pos[p] は常に O[x][y] == p を満たす。

---

# 6. スコア

T ターン終了後:

各プレイヤー p について:

S_p = Σ（O[i][j] == p である全マス (i,j)）:
V[i][j] \* L[i][j]

スコア計算に到達可能性条件は不要です。

tester が用いるコンテストスコア:

SA = max_{p=1..M-1} S_p

Score = round(1e5 \* log2(1 + S_0 / SA))

---

# 7. AIプレイヤーの行動

AIプレイヤー p（1 ≤ p ≤ M-1）について:

内部パラメータ:

- wa_p
- wb_p
- wc_p
- wd_p
- ε_p

評価値 A_p(i,j):

O[i][j] == -1 のとき:
A = V[i][j] \* wa_p

それ以外で O[i][j] == p のとき:
L[i][j] < U なら:
A = V[i][j] \* wb_p
それ以外:
A = 0

それ以外で O[i][j] != p のとき:
L[i][j] == 1 なら:
A = V[i][j] \* wc_p
それ以外:
A = V[i][j] \* wd_p

行動選択:

確率 ε_p で:
B_p から一様ランダムに1マス選択

確率 (1 - ε_p) で:
B_p 上の A の argmax 集合を M とし、
M から一様ランダムに1マス選択

ローカル tester の決定的実装詳細:

- 与えられた乱数表 r[p][2t], r[p][2t+1] を使用
- ε 分岐条件: r[p][2t] < ε_p
- K 個の候補から一様選択:
  idx = floor(r[p][2t+1] \* K), 上限を K-1 にクリップ
- Argmax の同値判定には許容誤差を使用:
  tol = 1e-9 \* max(|max_score|, 1.0)
  score[i] >= max_score - tol を同値最大とみなす

---

# 8. 同時性保証

全プレイヤーは:

- 同一状態 S を基準に行動選択する
- 衝突解決は全移動を同時に考慮する

優先順位は存在しません。

---

# 9. シミュレーションの決定性

決定的シミュレーションのために:

- 乱数が必要な箇所では seed 固定 RNG を使う。
- タイブレークは一様でなければならない。

---

# 10. 必須エンジン関数

任意のシミュレータは以下を実装する必要があります。

- compute_reachable(p)
- compute_legal_moves(p)
- resolve_conflicts(all_moves)
- apply_territory_updates()
- restore_removed_pieces()
- compute_score(p)

# 11. 問題I/O制約（問題文準拠）

本節は、ゲームメカニクスではなく「問題入出力で保証される値域」を整理したものです。

## 11.1 初期入力の制約

- N = 10
- 2 ≤ M ≤ 8
- T = 100
- 1 ≤ U ≤ 5
- 1 ≤ V[i][j]
- Σ_{i,j} V[i][j] = 1000 * N^2
- 0 ≤ sx_p, sy_p ≤ N-1
- 初期位置 (sx_p, sy_p) はプレイヤー間で相異なる

## 11.2 各ターンのI/O

解答プログラムは各ターンで `tx_0 ty_0` を出力する。
その後、ジャッジから以下が与えられる。

- 全プレイヤーの宣言移動先 (tx_p, ty_p)
- ターン終了時の全プレイヤー駒位置 (ex_p, ey_p)
- ターン終了時の所有者行列 O
- ターン終了時のレベル行列 L

値域制約:

- 0 ≤ tx_p, ty_p ≤ N-1
- 0 ≤ ex_p, ey_p ≤ N-1
- -1 ≤ O[i][j] ≤ M-1（O=-1 は無所有）
- 0 ≤ L[i][j] ≤ U

---

# 12. 入力生成方法（問題文準拠）

記号:

- randint(L, U): [L, U] の整数一様乱数
- randdouble(L, U): [L, U) の実数一様乱数

## 12.1 基本パラメータ

- M = randint(2, 8)
- U = randint(1, 5)
- 各初期位置 (sx_p, sy_p) は重複なしで一様ランダムに生成

## 12.2 マス価値 V の生成

1. a = randdouble(0.0, 3.0)
2. 各マスで V[i][j] = (randdouble(0.5, 1.0))^a
3. K = randint(0, 2) 回、以下を実施
   - x = randint(0, N-1), y = randint(0, N-1)
   - b = randdouble(1.0, 4.0)
   - m = randint(0, 4)
   - R = randdouble(1.0, 5.0)
   - 全マスに対し m に応じて加算
     - m=0: `+ b * exp(-((i-x)^2 + (j-y)^2) / (2R^2))`
     - m=1: `+ b / (1 + sqrt((i-x)^2 + (j-y)^2) / R)`
     - m=2: `(i-x)^2 + (j-y)^2 <= R^2` なら `+ b/4`
     - m=3: `+ b / (1 + (|i-x| + |j-y|) / R)`
     - m=4: `|i-x| + |j-y| <= R` なら `+ b/4`
4. S = ΣV として V[i][j] = ceil(V[i][j] * 1000 * N^2 / S)
5. ΣV > 1000 * N^2 の間、`V[i][j] >= 2` のマスから一様に1つ選んで V[i][j] を 1 減らす

## 12.3 AI内部パラメータの生成

各 AI プレイヤー p (1 ≤ p ≤ M-1) について:

- wa_p, wb_p, wc_p, wd_p は独立に randdouble(0.3, 1.0)
- ε_p は randdouble(0.1, 0.5)

---

# 13. ローカルテスタ入力の追加入力

ローカルテスタ用入力ファイルは、解答プログラムが受け取る初期入力の末尾に以下を追加する。

1. M-1 行: 各AIの内部パラメータ `wa_p wb_p wc_p wd_p ε_p`
2. T*(M-1) 行: 行動選択用乱数 `r1_{t,p} r2_{t,p}`（各値は [0,1) の一様乱数）

用途:

- r1_{t,p}: ランダム行動 / 貪欲行動の分岐
- r2_{t,p}: 候補集合からのインデックス選択

---

# 14. コンテスト採点（補足）

本仕様のエンジンが返す 1 ケース絶対スコアは第6節の通り。
コンテスト順位表はさらに相対評価で計算される。

- ケース相対評価: round(1e9 * 自身の絶対スコア / そのケースの参加者内最大絶対スコア)
- 提出スコア: 全ケースの相対評価和
- テストケース数:
  - 暫定: 100
  - システム: 3000
